# Factoria AI Context

This document provides architectural context for AI assistants working on the **Factoria** codebase.

Factoria is an **AI workflow orchestration system** that converts development tickets into artifacts and pull requests through a sequence of specialized agents.

Assistants should read this document before modifying the system.

---

# System Overview

Factoria orchestrates a workflow where a ticket progresses through several states.  
At each state, an AI agent generates artifacts that contribute to the final pull request.

Example workflow:

TICKET_INTAKE → DESIGN_REVIEW → PROFILING → BUILD → QA → PR_CREATION

Artifacts generated by agents are stored in a workspace directory and registered in the database.

# Workflow Engine

The workflow engine controls state transitions.

Location:


api/app/services/orchestrator.py


Responsibilities:

- Advance workflow states
- Emit state transition events
- Queue agents for execution

Example transition:


TICKET_INTAKE → DESIGN_REVIEW


Each transition produces a `workflow_event`.

---

# Workflow Definition

Workflow structure is defined in:


api/app/workflows/ticket_to_pr.py


Important structures:


WORKFLOW_GRAPH
STATE_AGENT_MAP


Example:


WORKFLOW_GRAPH = {
"TICKET_INTAKE": "DESIGN_REVIEW",
"DESIGN_REVIEW": "PROFILING",
"PROFILING": "BUILD",
"BUILD": "QA",
"QA": "PR_CREATION"
}


Agents mapped to states:


STATE_AGENT_MAP = {
"TICKET_INTAKE": "IntakeAgent",
"DESIGN_REVIEW": "DesignAgent",
"PROFILING": "ProfilerAgent",
"BUILD": "BuilderAgent",
"QA": "QAAgent",
"PR_CREATION": "PRAgent"
}

# Worker System

Agents are executed asynchronously by workers.

Worker location:


api/app/workers/agent_worker.py


Responsibilities:

- Poll `AgentTask` table
- Execute agents
- Write artifacts
- Mark tasks completed

Worker loop:


pending AgentTask
→ run agent
→ write artifact
→ emit event
→ orchestrator advances workflow


---

# Agent Execution

Agents are executed through OpenClaw.

Location:


api/app/services/openclaw_service.py


The worker calls:


AgentRunner.run_for_state()


Responsibilities:

- Prevent duplicate agent runs
- Start OpenClaw agent
- Write artifact files
- Register artifact in database

# Development Guidelines

When modifying the system:

1. Do not break the workflow state machine.
2. Ensure new states have a corresponding agent.
3. Ensure agents generate artifacts.
4. Ensure workflow events are emitted for state transitions.

---

# Common Debugging Steps

If artifacts are missing:

1. Check worker logs.
2. Verify `STATE_AGENT_MAP`.
3. Verify `WORKFLOW_GRAPH`.
4. Verify workflow state transitions.
5. Check AgentTask queue.

Factoria aims to provide a deterministic AI workflow engine capable of converting tickets into pull requests through coordinated agent execution.
